# McpGo — вопросы о доверии, доступах и работе проекта

Эта страница предназначена для человека, который впервые видит репозиторий и хочет разобраться, **что именно запускается на его Mac**.

## McpGo — облачный сервис?

Нет. В текущем дизайне McpGo — локальный macOS control plane. Однако терминальный/browser MCP использует внешнее подключение к выбранному ChatGPT workspace через Secure MCP tunnels, а Chrome продолжает общаться с сайтами в интернете. Поэтому «локальное приложение» не равно «нет сетевых передач».

## Разработчик видит мой рабочий стол или вкладки?

Собственного удалённого кабинета разработчика для просмотра экранов в текущей архитектуре не описано. Но **разрешённый MCP-клиент** может получать результаты браузерных и терминальных инструментов. Если он имеет browser-tools в вашем личном Chrome, он может увидеть содержимое разрешённых вкладок. Именно поэтому нельзя подключать этот tool surface к недоверенному workspace.

## Почему McpGo нужен доступ к терминалу?

ChatTerminalHub выполняет пользовательские команды и jobs. Это основная функция продукта, а не техническая мелочь. Права равны возможностям macOS user, под которым работает процесс; полной изоляции shell нет. Использовать следует только с клиентом, которому вы разрешаете такие действия.

## Почему не отдельный Chromium?

Текущий сценарий рассчитан на **личный уже запущенный Chrome**, чтобы видеть настоящие вкладки и работать в существующем контексте. Это удобнее, но риск выше: он не изолирует рабочие веб-сессии от автоматизации. Chrome показывает собственный запрос/разрешение CDP, которое должен подтвердить пользователь.

## Можно ли запретить доступ к определённой вкладке?

Текущий backend использует shared Chrome context и не заявляет полноценную per-tab ACL. Не следует считать, что визуальное отсутствие вкладки в UI равно запрету её чтения. Для строгой изоляции нужна отдельная разработанная policy и тесты; она указана в roadmap.

## Какими инструментами можно пользоваться?

Терминал поддерживает PTY, OneShot и detached jobs. Browser MCP предоставляет разрешённые Playwright tools через proxy. В proxy явно блокируется `browser_run_code_unsafe`; это **не** означает, что все другие tools read-only. Полный surface проверяется через MCP `tools/list` в вашей установке.

## Будут ли мои чаты скопированы в McpGo?

Нет, Messenger хранит только **явно опубликованные** сообщения агентской очереди. Полная история ChatGPT не экспортируется автоматически. AutoSend взаимодействует с заданным чатом через браузер пользователя и может отправить туда текст, если пользователь создал и включил расписание.

## Может ли AutoSend отправить два раза?

Система специально фиксирует `click-committed` до нажатия Send и при неоднозначном результате запрещает автоматический повтор. Это уменьшает риск дубликата, но **не математическая гарантия exactly-once**: DOM и браузерная сессия могут вести себя непредсказуемо. Для ответственных действий предусмотрен `unknown` и ручная проверка.

## Что происходит, если Mac спит?

Работа, требующая Chrome/локального runtime, не может гарантированно выполняться, пока Mac спит или закрыт. Проверка назначенного времени продолжится после возвращения среды в рабочее состояние согласно текущим правилам scheduler.

## Почему службы называются com.mcphub, а продукт McpGo?

Это сохранённые system IDs текущей установки. Их массовая замена может сломать старые LaunchAgents, разрешения, хранилища и подключение. Видимое имя уже McpGo; для полной миграции ID необходим отдельный версионированный migration+rollback.

## Могу ли я установить проект на любой Mac?

**Пока нет обещанного portable installer.** Референс-установка рассчитана на конкретную macOS конфигурацию. Часть paths/launchd scripts ещё содержит абсолютные пути. Документ [PACKAGING.md](PACKAGING.md) описывает, что требуется для независимого распространения.

## Как узнать, что бинарник соответствует исходникам?

В текущей локальной сборке нет публичного signed release provenance. Для полноценного ответа нужен проверенный Git tag/commit, воспроизводимая сборка, checksums, SBOM и Developer ID signing/notarization. До реализации этих механизмов следует **собирать из самостоятельно просмотренных исходников**, а не доверять случайному `.app` архиву.

## Где посмотреть, какие службы он запускает?

```bash
launchctl list | grep -E 'com.chatterminalhub|com.mcphub'
```

Список label и `ProgramArguments` см. в [CONFIGURATION.md](CONFIGURATION.md). Запущенная служба не обязательно означает доступный извне MCP tool.

## Как удалить личные данные?

Очередь Messaging находится в SQLite, задания AutoSend — в JSON-state. Удаление задачи и очистка журнала имеют разные последствия. Содержимое Chrome и серверные чаты ChatGPT удаляются только средствами соответствующих продуктов. Универсальный data uninstaller McpGo пока не реализован; детали и ограничения — [DATA.md](DATA.md).

## Какие есть гарантии безопасности?

Проверяемые: loopback binding, некоторые проверки Host/Origin, PTY capability, отложенная отправка при busy, запрет автоматического повтора после потенциального клика, тесты. **Не подтверждены**: внешний pentest, строгая sandbox изоляция, аттестация release binary, гарантия отсутствия любых уязвимостей. Это явно описано в [THREAT_MODEL.md](THREAT_MODEL.md).

## Как я сам проверю проект?

Пройдите [AUDIT_GUIDE.md](AUDIT_GUIDE.md): там указаны исходные файлы, что в них искать и какие команды безопасно запускать. Затем выполните тесты из [VERIFICATION.md](VERIFICATION.md). Если проверка не выполнялась, пишите NOT RUN — не заменяйте это фразой «всё отлично».

## Почему документация такая подробная?

Потому что программа получает серьёзные полномочия. Лучшее доказательство добросовестности — прозрачная архитектура, проверяемые границы, работающий open-source процесс и объяснение рисков. Длинная документация сама по себе **не** является независимой экспертизой, но должна сделать её возможной.
