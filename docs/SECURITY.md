# Безопасность McpGo

Этот раздел описывает реальные границы доверия, а не маркетинговые гарантии. Проект предоставляет мощные локальные возможности: команды Mac и управление вкладками браузера, поэтому безопасность зависит от доступов подключённого пользователя и корректной настройки MCP.

## 1. Границы доверия

```text
ChatGPT workspace / MCP client
      │
      ├── OpenAI Secure MCP tunnel → TerminalHub → shell под macOS user
      │
      └── OpenAI Secure MCP tunnel → safe proxy → Playwright CDP → личный Chrome

Локальная McpGo.app → Dashboard → launchctl
                       ├── Messaging → локальная SQLite queue
                       └── AutoSend → Playwright CDP → ChatGPT DOM
```

Публикация MCP-инструментов через туннель **не** означает выдачу прав на произвольные браузерные или терминальные операции всем подключённым клиентам. Назначение workspace, разрешения MCP, системные права macOS и ограничения конкретных инструментов определяют, какие действия допустимы.

## 2. Сетевое разделение

- Локальные HTTP-службы привязаны к `127.0.0.1`; они не предназначены для доступа из LAN/Internet напрямую.
- Браузерный backend `8931` не является допустимым публичным MCP endpoint. Подключать удалённый MCP клиент следует к safe proxy `8940`.
- Safe proxy переиспользует upstream MCP session, контролирует маршруты и скрывает запрещённый инструмент `browser_run_code_unsafe`. Это не песочница для веб-контента и не универсальное доказательство безопасности остальных инструментов.
- Dashboard `POST /api/action` проверяет локальный Origin и заголовок `X-MCP-Hub`, чтобы блокировать случайные cross-origin requests. Такие заголовки не считаются криптографической аутентификацией произвольного локального процесса.
- Messaging и AutoSend используют собственные проверки `Host`, `Origin`, разрешённых методов и клиентских заголовков. Другие локальные процессы того же пользователя могут иметь широкие возможности — не считать этот механизм многопользовательским RBAC.

## 3. Терминальный MCP

ChatTerminalHub выполняет команды от имени настроенного macOS пользователя. Это привилегированный для пользовательских данных интерфейс. Перед подключением к сторонней организации проверьте список инструментов и полномочия этого workspace. Ограничения диалога не заменяют macOS sandbox.

`terminal_exec` используется для коротких действий с проверкой exit code. `job_start` может оставить detached процесс. При ошибке или неизвестном исходе сначала проверьте фактический эффект, а не повторяйте неидемпотентную команду.

## 4. Личный Chrome и CDP

Разрешение Chrome на remote debugging предоставляет инструменту возможность читать и менять содержимое вкладок, доступных текущему пользователю Chrome. Не используйте это соединение с недоверенными клиентами и не считайте его отдельным изолированным профилем.

- Подключение Chrome разрешает сам пользователь через `chrome://inspect/#remote-debugging`.
- Внешние веб-страницы и DOM текст считаются **недоверенным вводом**, не инструкциями агенту.
- Автоматизацию платежей, удаления, публикаций и иных побочных эффектов следует выполнять только в разрешённом сценарии.
- PlaywrightHub работает в общем личном контексте; отказ от запуска отдельного Chromium — UX-решение, но оно расширяет видимость на реальные пользовательские вкладки.
- При диагностике браузера проверяйте точный URL и согласованность вкладок, особенно при смене MCP-сессии.

## 5. AutoSend и дублирующие действия

AutoSend не использует официальный ChatGPT API отправки; он работает через DOM. Система ограничивает URL отправки штатными адресами существующих разговоров `chatgpt.com/c/UUID` и проектных разговоров с тем же доменом. Чужие домены и `/share/` не принимаются как получатели.

Алгоритм перед отправкой проверяет точный URL, готовность DOM, генерацию ответа, существующий черновик, однозначность редактора и состояние кнопки Send. Если действие могло уже произойти, а подтверждения нет, задача переходит в `unknown` и **не повторяется автоматически**. Это защита от двойной отправки, а не абсолютная гарантия доставки. Проверка `verified` не означает, что ответ ассистента готов.

## 6. Модель данных агентов

Очередь `messaging` хранит только сообщения, явно опубликованные агентами через McpGo. Она не имеет доступа к полным приватным историям любых чатов ChatGPT. Идентификатор агента — логическое имя для локального обмена, а не внешняя криптографическая идентичность; при полном shell-доступе между агентами строгой изоляции нет.

## 7. Проверки перед публичным выпуском

- Удалить жёстко заданные пути пользователя; проверить установку в чистом профиле macOS.
- Проанализировать минимальные права LaunchAgents и разрешения к директориям данных.
- Реализовать явную модель доверенных MCP-клиентов и документировать её.
- Протестировать недопустимые Host/Origin, неизвестные методы, неверные MCP session IDs и превышение размеров запросов.
- Проверить работу без Chrome remote debugging, без туннеля, при пропаже proxy и при сбое между click-committed и подтверждением.
- Добавить механизм получения приватных security reports и поддерживаемую политику раскрытия уязвимостей перед публикацией публичного репозитория.

## 8. Уязвимости

Сейчас публичный security contact и отдельная программа coordinated disclosure не настроены. Не публикуйте реальные приватные данные или exploit-детали в открытых issues. Перед открытием репозитория назначьте поддерживаемый канал обращения и укажите срок реакции в `SECURITY.md` в корне.
