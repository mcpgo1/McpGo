# McpGo — ребрендинг, технические идентификаторы и миграция

Дата: 06.11.2026. Название продукта: **McpGo** (точный регистр). Историческое пользовательское название: «MCP Hub». Цель: изменить видимый бренд без потери работающих MCP-туннелей, разрешений macOS, данных AutoSend, переписки агентов и установленных LaunchAgents.

## 1. Уже изменённые поверхности

- SwiftUI — заголовок окна и приложения, подписи, пользовательские тексты, главный тип `@main struct McpGo`.
- Веб-страница Dashboard — title, заголовок, текст о браузере CDP.
- App bundle — `McpGo.app`; `CFBundleName` и `CFBundleDisplayName` = `McpGo`.
- Новая команда открытия — `Открыть McpGo.command`.
- README и актуальная техническая документация; навыки в `skills/` и подписанных ресурсах приложения.

## 2. Что осталось с историческим названием — намеренно

| Legacy значение | Почему сохраняется | Что потребуется для удаления |
|---|---|---|
| `<INSTALL_ROOT>` | Абсолютные пути в shell, LaunchAgents, SwiftUI, Playwright | Inventory всех ссылок, перенос рабочего каталога, симлинки, реустановка plist, проверка |
| `com.mcphub.dashboard` / `com.mcphub.messaging` / `com.mcphub.autosend` | Идентификаторы launchd и API-клиентов | Новый label, перевод клиентов, stop/bootout старых только после здоровья новых |
| `com.mcphub.playwright.*` | Три работающих компонента браузера | Одновременная миграция dashboard groups, plist, установленных служб и туннеля |
| `local.mcphub.native` | Identity bundle и сохранённые системные права | Новый Bundle ID, независимая подпись/права, ручная проверка доступов |
| `MCPHub` Mach-O / CFBundleExecutable | Исполняемый файл внутри bundle и сценарии сборки | Согласованная замена имени файла + Info.plist + упаковка |
| `X-MCPHub-Client` / `X-MCPHub-Extension` | Жёсткие заголовки локальных HTTP handlers | Двухсторонняя смена серверов и клиентов + версии API |
| `~/Library/Application Support/MCPHub/AutoSend` | Живые расписания/попытки | Атомарная миграция с backup и SQLite/JSON consistency |
| Keychain service identifiers | Привязка текущих настроек туннелей | Перенос через Keychain API и подтверждение доступности |
| `MCP Hub.app` alias | Старые команды открытия и пути | Проверка всех внешних зависимостей и deprecation period |

Эти идентификаторы — **совместимость, а не публичный брендинг**. Сломанные права Chrome или потерянный Tunnel ID могут быть следствием их преждевременной замены.

## 3. Текущая схема путей

```text
~/Desktop/McpGo                → symlink на ~/Desktop/mcphub
~/Desktop/mcphub/McpGo.app     → фактический bundle
~/Desktop/mcphub/MCP Hub.app   → symlink на McpGo.app
~/Desktop/mcphub/Открыть McpGo.command → новый пользовательский launcher
~/Desktop/mcphub/Открыть MCP Hub.command → прежняя точка входа, сохранена
```

При копировании приложения через Finder нельзя ожидать сохранения абсолютных путей без их перенастройки. Для чистой установки на новом Mac требуется отдельная проверка packaging и переносимости; текущее решение рассчитано на существующий Mac.

## 4. Будущая полная миграция system IDs — отдельный проект

1. Составить машиночитаемый inventory: LaunchAgents, SwiftUI, Dashboard, JS, Python, plist, логи, Keychain, shell wrappers, data paths.
2. Сохранить согласованные backup всех пользовательских данных. Зафиксировать работающий до миграции snapshot служб, портов и E2E вызовов.
3. Реализовать dual-read и backward compatible aliases для нового и старого идентификаторов; не менять формат базы без versioning.
4. Установить новые plist без одновременного запуска **двух копий AutoSend** (иначе возможны дубликаты). Переместить/скопировать данные атомарно, дождаться подтверждения работы.
5. Перевести SwiftUI и dashboard на новые labels/API, протестировать простой запуск, перезапуск и старт после log in.
6. Только после проверки всех сервисов вывести старые plist из эксплуатации. Не удалять текущие данные до успешной стабилизации.
7. Отдельно проверить возврат на прежнюю версию. Миграция без rollback не считается готовой.

## 5. Критерии приемки бренда

- Все пользовательские заголовки, меню, тексты и новые документы показывают McpGo.
- Подписанный `McpGo.app` проходит codesign verify и macOS launch.
- Шесть MCP LaunchAgents доступны, два туннеля подключаются, TerminalHub и PlaywrightHub отвечают реальным вызовом.
- Очередь агентов и AutoSend сохранили расписания, историю и чаты; без тестовой автоматической публикации в рабочие беседы.
- Ни одно изменение документации не рекомендует использовать старый Chromium или расширение как действующий AutoSend-транспорт.
