# Браузер McpGo

## Выбранный способ

**Только официальный Playwright MCP Extension** в Chrome/Edge, без CDP endpoint, отдельного Chromium или собственного Native Messaging расширения. См. [официальную документацию](https://playwright.dev/mcp/configuration/browser-extension).

- Browser MCP: backend `127.0.0.1:8931` с официальным Extension и общий безопасный MCP proxy `127.0.0.1:8940`, предоставленный ChatGPT через Secure MCP Tunnel. Группа браузерных агентов `MCPGO`.
- AutoSend: **независимый постоянный backend `127.0.0.1:8932`**, тот же официальный Extension, но отдельный клиент/группа `MCPGO AutoSend`. Его использует только локальный планировщик `127.0.0.1:8972`.
- Эти подключения не переходят друг в друга, не обмениваются правами и не полагаются на общий активный tab index.

## Настройка расширения

Установите [официальное Playwright Extension](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm) в Chrome/Edge через кнопку в мастере McpGo (Chrome Web Store; подтвердите разрешения в самом браузере) и один раз разрешите клиенту `MCPGO` работать со своими вкладками. В macOS токен расширения хранится в `~/Library/Application Support/McpGo/playwright/extension-token`; настройка через защищённое поле мастера или резервный CLI `bash playwright/configure-extension.sh` (запускайте интерактивно; после настройки через CLI перезапустите Browser MCP). В Windows используется официальный Extension в выбранном Chrome/Edge.

У отдельного клиента AutoSend собственная группа. Чтобы задать расписание для разговора, сперва откройте его в браузере и выберите/переместите **одну** вкладку в группу AutoSend. После этого нажмите в McpGo «Проверить без отправки». AutoSend не создаёт и не перезагружает вкладки автоматически, даже когда нужная вкладка отсутствует.

## Протокольная проверка backend и proxy

`playwright/probe.mjs` принимает `PLAYWRIGHT_MCP_PROBE_MODE=direct|proxy` для явного выбора протокола. `direct` выполняет стандартный `initialize` и сохраняет MCP session; `proxy` использует modern discovery и workspace для проверки вкладок. Без override сохранено прежнее поведение: порт `8931` — direct, остальные порты и внешние URL — proxy. Неизвестное значение завершается ошибкой до HTTP-запросов.

Мастер и `playwright/try-extension.sh` явно выбирают `direct` для временного официального backend на `8999`; итоговая проверка мастера на `8931` наследует тот же режим. Успешные `initialize` / `tools/list` не доказывают авторизацию расширения или доступ к вкладкам: для этого нужна отдельная проверка `PLAYWRIGHT_MCP_VERIFY_TABS=1` с разрешения пользователя.

Регрессии без Chrome и пользовательских данных: `node --test playwright/probe.test.mjs` и `python3 -m unittest discover -s onboarding -p test_extension_probe_mode.py -v`. Для отката исходников до релиза верните три изменённых runtime-файла из предыдущей версии; переустановка расширения или изменение токена для отката этого патча не требуется.

## Владение workspace при переподключении

McpGo не считает `openai/session` постоянным идентификатором разговора: ChatGPT может менять его между MCP-вызовами. В MCP 2026-07-28 сначала вызови `mcpgo_workspace`, затем **при каждом** вызове `browser_tabs`, `browser_snapshot`, `browser_navigate`, `browser_click` и других браузерных инструментов передавай полученный **свой** `workspace_id`. Параметр включён в схему инструментов и повторяется в результатах. Если подключение само передаёт стабильный `x-mcpgo-conversation-id`, владелец может определяться автоматически.

В старом MCP новое транспортное подключение тоже может получить новый внутренний ID. Без стабильного заголовка восстанови прежний workspace вызовом `mcpgo_workspace({workspace_id: "..."})` и продолжай передавать его в последующих вызовах. **Нельзя угадывать владельца по имени MCP-клиента, URL или активной вкладке:** разные агенты могут открывать одинаковые страницы. При отсутствии стабильного заголовка и собственного сохранённого `workspace_id` требуется новая явная привязка.

При конфликте `TAB_OWNED_BY_ANOTHER_AGENT` диагностика показывает только краткие обезличенные псевдонимы владельца и вызывающего агента, не логирует адреса, содержимое страниц, токены или сам `workspace_id`. Внешний workspace ID нельзя передавать другому агенту: идентификатор является приватной возможностью восстановления, а не доказательством личности собеседника. При **полном перезапуске процесса прокси** прежние временные аренды и дескрипторы вкладок сбрасываются; без стабильного Chrome tab ID от официального Playwright MCP гарантировать прежнее физическое владение невозможно. Нужна явная повторная привязка, а не автоматический захват.

## Изоляция и ограничения

Playwright MCP публично предоставляет `browser_tabs(list/new/close/select)` с индексами, а не постоянными Chrome tab IDs. Не считать индекс постоянным идентификатором! Выделенная группа и требование ровно одной совпадающей вкладки являются принципиальной частью дизайна AutoSend. Если группа содержит две одинаковые вкладки, AutoSend не выбирает ни одну из них. См. [ADR-001](adr/001-autosend-extension-only.md).

MCP proxy сериализует изменяющие команды основного Browser MCP, ведёт receipts для защиты от повторных действий и не допускает чужих запросов к закреплённым группам. Scheduler не использует этот proxy и не конкурирует с браузерными агентами за их текущую вкладку.

Локальные порты предназначены только для loopback. При сетевом обрыве браузерного вызова нельзя автоматически повторять действие, которое могло уже выполниться. Не раскрывайте токены расширения, MCP tunnel или пользовательские cookies в логах.
